# AI Agent Instructions
## Purpose
This subdirectory contains the BSOD Detector tool for OpenShift Virtualization testing. It detects, captures, and analyzes Blue Screen of Death (BSOD) evidence from Windows guest VMs (bug-check codes, crash dumps, event logs, host/KVM correlation signals).

## Local Conventions
- Scripts as tooling: deterministic operations live in scripts with clear stdin/stdout contracts (prefer JSON to stdout).
- Single source-of-truth: bug-check code tables, driver mappings, and log source names come from JSON files in `src/data/`.
- Host vs guest split: host/KubeVirt orchestration under `src/scripts/host/`; Windows guest scripts under `src/scripts/guest/` (PowerShell unless there is a reason to use another language).
- No hardcoded duplicated data across scripts.
- Build artifacts (`*.sys`, `*.exe`) are git-ignored and rebuilt from source.

## Notes
**For detailed operational and configuration information, see [README.md](README.md).**
- Detection is implicit: catches ANY bug-check code via WER System/1001 event
- `src/data/trigger-methods.json` defines codes deliberately exercised in CI via a KeBugCheckEx test driver
- The KVM test harness (`vm/`) is Linux-host-side; guest configuration/validation scripts are Windows-guest-side
- Driver Verifier ON in test VMs changes some bug-check outcomes; data files record codes as observed
- Crash dumps may contain host-identifying data; never commit captured dumps (`output/` is git-ignored)

**Key architectural decisions:**
- Pipeline stages: `preflight-rhov.sh` → `watch-crash.sh` → `extract--guest-os--crash-info.sh`, with shared metadata and evidence-mount contracts
- Guest crash settings are validated read-only against `crash-control.json` (golden image is the source of truth; host does not repair settings)

**Non-obvious constraints:**
- Evidence output must sit on a validated persistent mount (distinct mount or test-mode identity marker)
- Fail-closed: missing helpers, RBAC, storage, QGA, or validator mismatches abort before arming
- Prefer app-scoped history in [`.AI_HISTORY.md`](.AI_HISTORY.md) for significant changes in this directory
