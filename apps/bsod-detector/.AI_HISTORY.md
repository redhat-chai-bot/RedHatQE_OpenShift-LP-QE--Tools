### Added src/scripts/host/stakeout.sh — natural-BSOD campaign runner
- New host-side orchestrator for the whole natural-BSOD campaign: **preflight → stage → watch → escalate → verdict**. Subcommands `preflight`, `stage`, `watch`, `escalate`. It composes the existing scripts rather than reimplementing them; detection still belongs to `watch-crash.sh`.
- **Closes the hard-freeze gap, which was the reason to build it.** `watch-crash.sh` logged "guest dump is not retrievable from a frozen guest" and returned — but a frozen guest still holds its memory in host RAM, so that was the highest-value capture window and the last one before anyone power-cycles the VM. `capture-host-dump.sh` and `collect-from-host.sh --mode recover` already existed for exactly this and were simply never wired in. On KubeVirt the escalation dumps inside the virt-launcher pod and `oc cp`s the ELF out, converting with `elf2dmp` when available; the raw ELF is always preserved (review #5).
- **Adds a gating preflight**, which did not exist anywhere. Eleven read-only checks; the two that matter are `hyperv-enlightenments` (both `tlbflush` and `ipi` must be on or the TLB-flush crash cannot occur) and `split-lock-detect` (without it the `#AC` never appears *even when the crash happens*, so the only host-side attribution is lost). Under `--scenario tlb-flush` those are blockers; under `--scenario any` they demote to warnings. Previously you could stake out a VM for hours and only afterwards discover the evidence was never capturable.
- **Deliberately never mutates the VM or the node.** Fixing either blocker needs a VM restart or a node MachineConfig + reboot; on a shared cluster that is the operator's decision, so preflight prints the exact remedy and exits non-zero. Same reasoning for not shipping a workload generator — reproducing the TLB-flush hypercall pattern is workload-specific and nothing here is validated to do it, so there is a `--workload`/`--workload-guest` hook instead of a fake one.
- Introduces the **backend abstraction from review #3** (`--provider kubevirt|kvm|auto`, `BSOD_DET__HYP_PROV`) because it was forced: `watch-crash.sh` is `oc`-based and the recovery scripts are `virsh`-based, so something had to bridge them. `Virsh()` dispatches to `oc exec <virt-launcher> -- virsh` or bare `virsh`, and the domain is `<ns>_<vm>` or `<vm>` accordingly. Also surfaces review #6 (pvpanic changes the domstate seen at bugcheck) as a preflight check.
- `--dry-run` echoes every command instead of running it, and `--domain-xml`/`--node-cmdline` read those inputs from files (the same offline pattern `collect-host-signals.sh` already uses). Together these make the entire decision tree exercisable with no cluster — which is why it could actually be tested here rather than only written.

Full suite now 53 tests, all passing. (`run-tests.sh` globs the directory, so no runner change was needed.)
